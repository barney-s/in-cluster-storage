## Attempt Log

### Attempt 1:
- **What failed**: Bucket creation failed with `unrecognized arguments: --labels=repo-agent-instance=ics-kops1`.

### Attempt 2:
- **What failed**: `kops validate cluster` timed out after 10 minutes due to external GCE load balancer health check / public DNS routing delays. Additionally, the KOPS control plane service account binding failed because it was hardcoded but contains a random suffix on creation.
- **Evidence**:
  - `Get "https://34.45.201.88/api/v1/nodes": dial tcp 34.45.201.88:443: i/o timeout`
  - `Service account control-plane-ics-kops1-k8s-local@barni-cnrm-20260529.iam.gserviceaccount.com does not exist.`
- **What was changed**:
  1. Updated `deploy.sh` to dynamically query the KOPS control plane service account email via `gcloud iam service-accounts list --filter="email:control-plane-${CLUSTER}"` to handle the random suffix.
  2. Dynamically update `~/.kube/config` server address to point to the direct control plane VM's external NAT IP address (utilizing TLS SNI override `api.internal.ics-kops1.k8s.local` for complete secure TLS validation). This bypasses the load balancer's routing latencies entirely, enabling immediate and secure validation.

### Attempt 3:
- **What failed**: Parallel Cloud Builds failed with a pre-condition error during code tarball uploads.
- **Evidence**: `ERROR: (gcloud.builds.submit) 412 Could not upload file ... to [barni-cnrm-20260529_cloudbuild/source/...tgz]: The type of authentication token used for this request requires that Uniform Bucket Level Access be enabled.`
- **What was changed**: Configured `deploy.sh` to pre-emptively ensure Uniform Bucket Level Access (UBLA) is enabled on the cloudbuild bucket `gs://${GCP_PROJECT}_cloudbuild` before submitting builds.
