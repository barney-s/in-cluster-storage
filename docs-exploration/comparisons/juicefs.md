# Comparison: ObjectFS vs. JuiceFS

This document analyzes how **ObjectFS** differs from **JuiceFS** in its philosophy, architectural topology, metadata synchronization, and trade-offs.

---

## 1. Architectural Philosophy

While both filesystems provide POSIX-compliant shared storage backed by cloud object stores (S3/GCS), they target radically different deployment models and security boundaries.

### JuiceFS (Rich-Client Shared-Database)
*   **Decoupled Multi-Engine:** JuiceFS separates metadata from data blocks. The client (which mounts FUSE directly on the host or inside a container) connects directly to a **shared metadata database** (e.g., Redis, MySQL, TiKV, or SQL) and **directly to the cloud object storage** bucket.
*   **Security Boundary:** Every worker node mounting JuiceFS must have direct access (credentials/IAM) to the backing S3/GCS bucket and the central metadata database.

### ObjectFS (Credential-Isolated Centralized-Controller)
*   **Isolated Controller:** ObjectFS isolates cloud credentials and bucket metadata within a central, cluster-wide controller (`objectfs-controller`). The node-level daemons (`objectfs-node-daemon`) mount FUSE local directories and converse with the controller over gRPC.
*   **Security Boundary:** Worker nodes do not hold or see cloud storage credentials, protecting secret leaks under tenant compromise. The central controller enforces access boundaries and validates all operations.

---

## 2. Metadata & Invalidation Synchronization

| Feature / Dimension | JuiceFS | ObjectFS |
| :--- | :--- | :--- |
| **Topology** | Decentralized. Clients query a shared DB. | Centralized. Controller manages in-memory DB. |
| **Invalidation Feed** | Uses Redis 6.0+ Pub/Sub or Raft changelogs. | Dedicated persistent gRPC `WatchVolume` streams. |
| **Write Consistency** | Strong consistency (guaranteed by backing DB). | Eventual write-back consistency (3-tier buffering). |
| **Large File Reading** | Direct download from S3/GCS by client. | GCS/S3 signed redirect URLs generated by controller. |

### Metadata Invalidation Flows
*   **JuiceFS:** Uses database Pub/Sub or transaction streams to notify active clients to invalidate local `entry`/`inode` attributes. If a database disconnects, clients must periodically query or revalidate.
*   **ObjectFS:** Relies on gRPC streams (`WatchVolume`). The `objectfs-controller` broadcasts invalidation events to all subscribed node-daemons in real-time. If the connection drops, nodes currently rely on periodic fallback, but require a structured catchup protocol (see next steps).

---

## 3. Storage Efficiency and Data Path

*   **Zero-Copy & Data Chunking:** JuiceFS splits files into immutable 64MB blocks and smaller 4MB chunks to handle concurrent updates and append-only cloud APIs. ObjectFS writes through a 3-tier buffering model on local SSD/memory, and the controller commits larger blocks to cloud storage, generating signed URLs for high-throughput reads directly by nodes.
*   **Resource Footprint:** JuiceFS client running on every pod/node requires a continuous database connection and local memory buffers for database drivers. ObjectFS node-daemons are highly lightweight gRPC-only FUSE drivers.

---

## 4. Architectural Trade-offs

### JuiceFS Advantages
1.  **Maturity:** Highly optimized, battle-tested production filesystem with multi-database drivers.
2.  **Strong Database Consistency:** Transactions are enforced by the backing database (e.g. Redis/TiKV), offering instant consistency.
3.  **No Single Controller Bottleneck:** Direct S3 downloads and decentralized client queries mean no single API controller bottlenecks data throughput.

### ObjectFS Advantages
1.  **Zero-Trust Credential Isolation:** Absolute credential safety; compromised nodes can only read/write files they are explicitly authorized for.
2.  **Kubernetes-Native CSI Integration:** Extremely simple local configuration with minimal external dependencies (no separate Redis/SQL cluster needed).
3.  **Hybrid Signed Redirects:** The controller can offload direct data downloads to cloud storage APIs using signed URLs, keeping data paths extremely fast.
